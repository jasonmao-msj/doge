# Design: Enable doge Remote Updater

## Contract

| Surface | Contract |
| --- | --- |
| Update feed | `https://github.com/jasonmao-msj/doge/releases/latest/download/latest.json` |
| Trust anchor | user-provided doge minisign public key, embedded in `src-tauri/tauri.conf.json` |
| Signing secret | `TAURI_SIGNING_PRIVATE_KEY_B64` + `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, GitHub Actions only |
| macOS artifact | `doge_<arch>.app.tar.gz` + `.sig`, platform `darwin-aarch64` / `darwin-x86_64` |
| Windows artifact | signed `doge_*-setup.exe` + `.sig`, platform `windows-x86_64` |
| Update metadata | signed artifacts referenced by `latest.json`, generated by release workflow |

## Configuration flow

1. `config/brand.json` is the product identity source and changes `updater.enabled` to `true`.
2. Tauri base config enables the updater plugin, canonical endpoint, public key, and `createUpdaterArtifacts`.
3. Windows override independently enables `createUpdaterArtifacts`.
4. Release preflight validates the config and signing secrets before build jobs run.
5. macOS and Windows jobs build and sign platform artifacts; release job assembles `latest.json` and publishes it with the same GitHub release.

Artifact-only workflow dispatches are deliberately separate from publishing: the Windows job generates a temporary config with `createUpdaterArtifacts=false`, and the macOS build script accepts `--skip-updater-artifacts`. These jobs do not access release secrets and only produce unsigned/ad-hoc internal installers for startup checks.

## Runtime operation lifecycle

`useUpdater` remains the owner of the update state machine:

`idle -> checking -> available -> downloading -> installing -> restarting`

`error` is user-visible for interactive checks and install failures. A monotonically increasing operation token invalidates stale check/download continuations. Dismiss is enabled for `checking`, `available`, `latest`, and `error`, but disabled during `downloading`, `installing`, and `restarting`; there is no safe cancellation contract in the current Tauri API surface.

## Failure matrix

| Case | Required behavior |
| --- | --- |
| background feed/network failure | debug entry + `idle`, no visible failure toast |
| interactive feed/network failure | visible `error`, retry remains available |
| malformed/missing release artifact | release preflight/build fails, no partial release |
| stale check result | close stale handle and do not overwrite newer state |
| dismiss while download/install is active | control disabled; active operation keeps ownership and state |
| repeated update action while active | ignored; only one download/install operation may run |
| download/install failure | visible error, preserve progress, allow retry |

## Security and release decisions

- The public key is not secret and may be committed. The private key must never be present in repository files or logs.
- The old `ccgui` feed/key is not a valid trust source for doge and must not be restored.
- The first doge release must be published with the doge identity/version and then a second higher version is required for end-to-end update testing.
- Manual workflow dispatch must use `windows_artifact_only=false` and `macos_artifact_only=false` for a publishing release; artifact-only defaults are intentionally non-publishing.
